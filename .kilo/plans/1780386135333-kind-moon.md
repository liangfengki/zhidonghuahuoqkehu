# 分步式获客工作流实施计划

## 背景

当前 AI 中心采用"一键运行全流程"模式，用户无法在每个步骤中查看和确认中间结果。用户需要一个分步式工作流：采集邮箱 → 确认 → 生成邮件 → 确认 → 发送邮件 → 查看反馈，同时支持配置自己的邮箱账号进行发送。

## 现有架构分析

- **前端**: Next.js 15 + TanStack Query + Tailwind v4 (`apps/web/`)
- **后端**: NestJS + Prisma + BullMQ (`apps/api/`)
- **数据模型**: Contact、Campaign、CampaignContact、SendQueue、InboxThread、EmailAccount、AiEmailDraft 等已存在
- **现有功能**: 采集(`POST /leads/collect`)→队列异步处理、AI写邮件(`POST /settings/ai/trigger/run`)→一键全流程、收件箱(`GET /inbox/threads`)
- **缺失**: 分步控制、采集结果预览、单独生成邮件、用自己的邮箱发送

## 实施方案

### 1. 前端：新建工作流页面 `apps/web/src/app/workflow/page.tsx`

创建一个 4 步骤向导式页面，每步独立操作：

**Step 1 - 采集邮箱**
- 表单：关键词、行业、国家、指定公司域名、目标网址（用于网页爬取）
- 采集来源选择：Apollo API / Hunter API / 网页爬取（可多选）
- 点击"开始采集"→ 调用 `POST /workflow/collect`
- 轮询采集状态（每 2 秒 `GET /workflow/collect/:jobId/status`）
- 采集完成后自动展示结果列表

**Step 2 - 确认邮箱列表**
- 以表格展示采集到的邮箱：公司名、联系人、邮箱、职位、验证状态
- 支持全选/单选/删除不需要的邮箱
- 确认后点击"下一步：生成邮件"

**Step 3 - 生成邮件**
- 点击"为选中邮箱生成邮件"→ 调用 `POST /workflow/generate-emails`
- 展示生成的邮件草稿列表（主题、正文预览）
- 支持编辑每封邮件的内容
- 确认后点击"下一步：发送邮件"

**Step 4 - 发送邮件**
- 显示待发送邮件列表
- 选择发送邮箱（从已配置的 EmailAccount 中选择）
- 点击"发送"→ 调用 `POST /workflow/send`
- 发送完成后显示状态

**反馈展示区**
- 页面底部或侧边栏展示已发送邮件的回复/反馈
- 调用 `GET /workflow/feedback` 获取回复数据

### 2. 前端：设置页增加"我的邮箱"配置 `apps/web/src/app/settings/page.tsx`

在设置页新增"我的邮箱"tab：
- 表单：邮箱地址、SMTP 服务器、端口、用户名、密码、IMAP 服务器、端口
- 支持添加多个邮箱账号
- 支持测试连接（发送测试邮件验证 SMTP 配置）
- 显示已配置邮箱的状态和今日已发送数量

### 3. 后端：新增工作流 API 模块 `apps/api/src/workflow/`

**Controller: `workflow.controller.ts`**

| 端点 | 方法 | 说明 |
|------|------|------|
| `/workflow/collect` | POST | 发起邮箱采集任务 |
| `/workflow/collect/:jobId/status` | GET | 查询采集任务状态和结果 |
| `/workflow/contacts` | GET | 获取当前租户的联系人列表（支持筛选） |
| `/workflow/generate-emails` | POST | 为选中联系人生成 AI 邮件草稿 |
| `/workflow/drafts` | GET | 获取邮件草稿列表 |
| `/workflow/drafts/:id` | PUT | 编辑邮件草稿 |
| `/workflow/send` | POST | 发送邮件（支持指定 EmailAccount） |
| `/workflow/feedback` | GET | 获取已发送邮件的回复/反馈 |

**Service: `workflow.service.ts`**

- `collectEmails()`: 调用已有的 `QueueService.addCollectLeadsJob()`，支持 Apollo/Hunter/网页爬取三种来源，返回 jobId
- `getCollectStatus()`: 查询 BullMQ job 状态，完成时返回新增的 Contact 列表
- `generateEmails()`: 为选中联系人调用 AI API 生成邮件，存入 AiEmailDraft
- `sendEmails()`: 从指定的 EmailAccount 读取 SMTP 配置，通过 EmailEngine 发送
- `getFeedback()`: 查询 InboxThread + InboxMessage，返回有回复的线索

### 4. 后端：扩展队列服务 `apps/api/src/queue/queue.service.ts`

- 添加 `getJobStatus(jobId)` 方法，查询 BullMQ job 的状态和结果
- 在 collect-leads worker 完成时，将采集到的联系人 ID 列表存入 job return value

### 5. 后端：扩展 EmailEngine 支持 SMTP 发送 `packages/email-engine/src/sender.ts`

- 新增 `sendViaSmtp()` 方法，使用 nodemailer 直接通过用户配置的 SMTP 发送
- 在 `EmailSender.send()` 中添加 `'smtp'` provider 分支

### 6. 前端：侧边栏添加工作流入口 `apps/web/src/components/layout/sidebar.tsx`

在侧边栏添加"工作流"导航项，使用 `Workflow` 图标。

## 用户邮箱发送流程

1. 用户在"设置 → 我的邮箱"中添加自己的邮箱（SMTP/IMAP 配置）
2. 系统验证 SMTP 连接是否成功
3. 在工作流 Step 4 发送时，用户选择用自己的哪个邮箱发送
4. 系统通过该邮箱的 SMTP 配置直接发送邮件
5. 通过 IMAP 配置定期轮询收件箱，捕获回复到"反馈"区域
