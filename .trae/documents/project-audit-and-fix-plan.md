## 二、发现的问题清单

### 2.1 关键问题（影响运行）
1. **依赖未安装** - node_modules 不存在，需要运行 `pnpm install`
2. **缺少 .env 文件** - 需要从 `.env.example` 复制并配置实际值
3. **缺失前端页面** - `/campaigns` 和 `/leads/[id]` 页面不存在
4. **可能缺少 package.json** - `packages/queue-workers` 可能缺少配置文件

### 2.2 中等问题（影响功能）
5. **硬编码的 SMTP 凭据占位符** - 需要清理或配置化
6. **AI 调用逻辑重复** - WorkflowService 和 ai-engine 包存在两套实现
7. **无错误边界** - 前端缺少全局错误处理组件
8. **Supabase 客户端未使用** - 已引入但未实质使用

### 2.3 低等问题（影响质量）
9. **无测试框架** - 测试计划在 Phase 6
10. **无 TODO/FIXME 注释** - 代码中缺少开发标记
11. **DailyStats 字段类型** - 可能需要确认 Prisma 迁移行为

## 三、修复计划

### 3.1 第一阶段：环境准备和依赖安装
1. **安装项目依赖**
   ```bash
   pnpm install
   ```

2. **创建环境配置文件**
   - 复制 `apps/api/.env.example` 为 `apps/api/.env`
   - 配置数据库连接、JWT 密钥、Redis URL
   - 配置可选的第三方 API 密钥

3. **启动 Docker 基础设施**
   ```bash
   docker compose -f docker/docker-compose.yml up -d postgres redis
   ```

4. **数据库初始化**
   ```bash
   pnpm db:generate
   pnpm db:push
   ```

### 3.2 第二阶段：缺失页面开发
5. **创建 `/campaigns` 页面**
   - 文件：`apps/web/src/app/campaigns/page.tsx`
   - 功能：营销活动列表、创建、编辑、启动/暂停
   - 参考：现有 leads 页面的实现模式

6. **创建 `/leads/[id]` 详情页**
   - 文件：`apps/web/src/app/leads/[id]/page.tsx`
   - 功能：线索详细信息、联系历史、操作按钮
   - 参考：现有 inbox 详情页的实现模式

### 3.3 第三阶段：代码质量修复
7. **清理硬编码配置**
   - 移除 email-engine 和 queue-workers 中的硬编码 SMTP 凭据
   - 确保所有配置通过环境变量或数据库配置获取

8. **统一 AI 调用逻辑**
   - 检查 WorkflowService 中的 callAi 方法
   - 确保与 ai-engine 包的实现一致
   - 消除重复代码

9. **添加前端错误边界**
   - 创建全局 ErrorBoundary 组件
   - 在关键页面和组件中添加错误捕获

### 3.4 第四阶段：功能验证和预览
10. **启动全栈服务**
    ```bash
    # 终端 1：启动后端
    pnpm --filter @b2b-lead-gen/api dev
    
    # 终端 2：启动前端
    pnpm --filter @b2b-lead-gen/web dev
    
    # 终端 3：启动队列工作者（可选）
    pnpm --filter @b2b-lead-gen/queue-workers dev
    ```

11. **功能验证**
    - 测试用户注册/登录流程
    - 测试线索管理功能
    - 测试营销活动功能
    - 测试收件箱功能
    - 测试设置页面

12. **打开预览**
    - 前端：http://localhost:3000
    - 后端 API 文档：http://localhost:3001/api/docs
    - 数据库管理：Prisma Studio (`pnpm db:studio`)
